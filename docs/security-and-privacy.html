Sol Next 9.3.0 安全与隐私架构：零内置密钥、最小攻击面与端侧数据最小化

把手机操作权限交给 AI 智能体时，速度与精准度之外，隐私边界与防误操作安全是第一生命线。Sol Next 9.3.0 在设计阶段就采用零信任 BYOK、最小攻击面、端侧数据剪枝、单帧视觉滑窗、确定性防重发契约与硬件加密六重纵深防御，让每一项安全承诺都可以被开发者和用户独立验证。

1. 100% 零内置 Key & 零私有中转（可离线 Ollama）

公开版（ai.sol.next）通过构建期硬门禁禁止打包任何模型密钥与私服地址，不需要注册云账号；所有请求由手机直连你信任的官方厂商或局域网本地 Ollama / vLLM，彻底消除第三方代理窥探风险。

2. 最小攻击面（对比重型浏览器 + Linux Shell 沙箱）

刻意剔除嵌入式桌面浏览器引擎与每对话 Linux Shell 沙箱容器，收敛二进制体积与本地命令执行面；执行层严格收口于 10 个强类型正交 OS 工具，降低潜在提示词注入导致的越权面。

3. 端侧数据最小化：0 Token 直通 + Rust -97% 剪枝

查电量、存储、Wi-Fi、蓝牙、闹钟、验证码与通知直回走 72 ms Tier-0A 本地完成，数据 100% 不离机；复杂页面由 Rust v6.00 端侧剪枝剔除 -74% ~ -97% 无关节点后再发往模型，大幅减少无关聊天与屏幕 PII 暴露。

4. 单帧按需视觉滑窗（绝不持续录屏上云）

仅在 WebView、小程序、无标签图标页或 NO_CHANGE 时按需附带 1:1 Set-of-Mark 标注帧，并强制滑窗只保留最新 1 帧图像、即时淘汰历史截图，避免敏感界面在云端多轮上下文堆积。

5. 单次发送防重发契约 + 财务红线人工审批

微信发送按钮强制 4×85ms 只读气泡核验，送达状态不确定立即触发 SEND_CONFIRMATION_PENDING 停机（0 重发）；付款、转账、删除与 AI 电话均内置不可绕过的人工确认与「不付款不转账不承诺金额」红线。

6. Android KeyStore 硬件加密 + 供应链密码学校验

个人数字分身与偏好记忆基于 Android Hardware KeyStore AES-GCM 纯本地加密；每次发布公开完整 SHA256SUMS.txt 与固定签名证书指纹，支持独立验签与一行零密钥审计。
